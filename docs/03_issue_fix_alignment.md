## 0. 状态与使用约定

- **确认**：能直接从现有源码/配置/目录确认；“触发后果”仍可依赖实际输入。
- **条件风险**：需要真实数据、特定运行环境或对比实验验证，不能写成已经发生的故障。
- **协议/研究缺口**：设计尚未落地，或文档、脚本与论文主张不一致。
- **纠偏**：此前提过，但证据不足、表述过重或不应直接修改的点。
- **P0**：数据正确性、实验隔离、主张有效性或训练可用性；**P1**：明显的代码风险和关键复现缺口；**P2**：稳健性/工程与待验证的设计选择。优先级是建议，并非已量化损失。
- 当前 `data/{annotations,images,images_lit,raw}` 与 `results/` 仅有 `.gitkeep`；`configs/base.yaml:3-5` 的 LATeD-Spot JSONL 均不存在。没有真实数据或已产生的实验结果，**不能断言划分质量、模型性能、论文创新性或具体提升幅度**。仓库的 `docs/01_research_design.md:169-174` 也说明 PyTorch 路径此前仅做语法检查；本次未跑 PyTorch 训练/GPU 测试。

## 1. P0：必须先对齐的数据、训练与评测问题

### P0-01 数据文件和划分尚未真正生成（确认：交付缺口）
- **位置**：`configs/base.yaml:2-5`；`docs/02_dataset_protocol.md:32-39`；`data/annotations/`、`data/images/`。
- **现状/影响**：文档约定 LATeD 官方训练 1000 张划出 train 900 / val 100，官方 test 500；配置路径目前没有文件。现阶段无法核实图像、标注、转写、语种、各光照档数量，也无法启动正常训练。
- **修复对齐**：明确数据授权与获取来源；先冻结场景级 900/100/500 清单、固定种子及每张图唯一 ID；编写原始数据到 JSONL 的转换与 schema 检查，确保 JSONL 中 `image`/`lit` 路径在 `data.root` 下可解析。不要把文档数字当作已生成的数据。
- **验收**：三个 JSONL 与实际图像可逐条读取；train/val/test 图像、场景或招牌 ID 不交叉；输出图像/实例/可读文本/ignore/语种/档位计数及冻结清单哈希，test 仍是官方 500 张。

### P0-02 LATeD-Spot 转写与数据转换工作未落地（确认：交付缺口）

- **现状/影响**：训练识别器要求 `instances[].text`，但项目计划给原 LATeD 多边形补转写；现有仓库未提供这些转写、转换器或一致性报告。文档中的“13,923 实例”是待处理规模，**不是已完成的转写数**。
- **修复对齐**：确认原数据是否确无转写、许可与署名；建立原文转写、语言标签、不可辨认 `###`、双人核验/争议仲裁流程。所有来源统一转换到协议 JSONL，记录来源与变换版本。
- **验收**：训练集有效文本比例、`###` 比例、逐语种字符覆盖率、抽检错误率和标注一致率可复算；任意样本可回溯至原图及原标注。

### P0-03 验证集配置未进入训练（确认）
- **位置**：`configs/base.yaml:4`；`tools/train.py:37-57`。
- **触发/影响**：只创建 train DataLoader；每轮覆盖 `last.pt`，没有验证指标、最优 checkpoint 和早停。100 张验证集“用于选参”只存在于协议，当前训练无法据此选模型。
- **修复对齐**：建立 `train=False` 的独立验证加载器；复用 `tools/eval.py:25-34` 的坐标还原和 `SpottingEvaluator`；按阶段定义模型选择指标（检测预训练看 `det_F`、完整 spotting 看 `e2e_F`，避免一律看检测）；保存 `last` 与 `best`，阈值/早停只在 val 上选，最后锁定再测 test。
- **验收**：每次验证都有样本数与非空指标日志；仅 val 指标改变 `best`；用人为设置的不同验证结果能验证 best 选择和早停逻辑；test 不参与参数选择。

### P0-04 三阶段训练与实际实验脚本不一致（确认）
- **位置**：`tools/train.py:23-36`；`configs/base.yaml:39-41`；`scripts/run_baselines.sh:9-12`；`docs/01_research_design.md:91-94`。
- **触发/影响**：脚本直接训练 `seeread_joint` 和消融，未先跑 `det`、`rec`，也未传 `init_det`、`init_rec`。它得到的不是文档主张的 `det → rec → joint` 对比实验；不能把两种设定的数字混报。
- **修复对齐**：实验编排显式记录各阶段训练集、起止 checkpoint、冻结模块、训练轮数及权重继承；消融与主方法遵循**相同**数据和阶段/算力预算；如另试从头联合训练，要单列实验。
- **验收**：日志/元数据可追踪 `s1_det → s2_rec → s3_joint`；输入 checkpoint 与最终 checkpoint 权重可验证；主方法和消融使用相同预训练来源。

### P0-05 `rec` 阶段实际上可能使用预测高度（确认）
- **位置**：`tools/train.py:47`；`seeread/models/seeread.py:42-49`。
- **触发/影响**：`pred_geom_prob` 无阶段限制，随所有训练阶段的 step 上升；`rec` 阶段虽冻结检测器，也可能切到其预测高度，违反“GT 几何训练识别器”的阶段定义。
- **修复对齐**：将几何课程仅用于约定的 `joint` 阶段，`rec` 阶段明确固定为 GT；或者修改论文/协议，声明 `rec` 阶段也采用冻结检测器的预测高度。
- **验收**：针对 `stage=rec`、`stage=joint` 分别统计 GT/预测高度使用率，和书面设定完全一致。

### P0-06 测试集隔离规则与批量实验脚本冲突（确认：协议风险，非已发生泄漏）
- **位置**：`docs/02_dataset_protocol.md:35-39`；`scripts/run_baselines.sh:4,9-13`。
- **触发/影响**：协议写 LATeD 官方 test“只在定稿时评一次”，脚本却每个 seed×配置均直接跑 test。多次评估本身不等于泄漏；**一旦据 test 选择模型、调阈值或改消融方案，就构成测试集反馈污染**。
- **修复对齐**：把脚本常规评测目标改为 val；预先冻结模型/阈值/消融后统一一次性测试；test 可以报告每个预注册种子的指标，但不能用于开发决策。
- **验收**：开发日志无 test 驱动选择；结果表含固定方案与预定义种子；test 调用有可追踪的最终评测记录。

### P0-07 ESTR-v2“仅测试”与 CIC 配对训练的设定冲突（确认：协议冲突，非已发生泄漏）
- **位置**：`docs/01_research_design.md:99-104`；`seeread/models/seeread.py:51-63`。
- **触发/影响**：ESTR-v2 被写作只做跨域测试，同时其暗/亮配对又被提议用于训练 CIC。若用同一场景的任意一帧训练，再在它上面报跨域测试，独立性失效。
- **修复对齐**：二选一：ESTR-v2 全部作为严格盲测，仅从训练来源获取 CIC 配对；或事先按场景划分 train-pair/test-xdomain，两者不重叠，并改写“纯跨域测试”主张。
- **验收**：任何测试场景 ID/设备连拍组不在训练/CIC 清单中；实验配置可证明训练脚本从未读取保留测试图。

### P0-08 默认字符集使未知字符变成错误监督（确认）
- **位置**：`configs/base.yaml:17-20`；`seeread/models/recognizer.py:9,17-21,55-60`。
- **触发/影响**：默认 `0-9a-z`，`encode()` 丢弃其他字符；纯中文等编码为空时被 `or [1]` 转成类别 1（即字符 `0`），不是忽略样本。混合中英文会静默丢字，导致有偏标签。
- **修复对齐**：按**仅训练集**最终转写构造并冻结字符表；在训练前检查 OOV 比例，区分“忽略/拒绝/扩表”策略，禁止将空编码当 `0`；模型与 checkpoint 同时固化字符表/归一化版本，val/test 只报告 OOV 而不反向改表。
- **验收**：纯中文不会生成“0”标签；任意有效 GT 编码后可逆（或显式标记 OOV）；train/val/test 的 OOV 统计可复核。**注意**：之前建议“继续静默跳过 OOV”是不安全的，不采纳。

### P0-09 混合配对/非配对 batch 会整体丢失 CIC（确认）
- **位置**：`seeread/data/datasets.py:94-107`；`seeread/models/seeread.py:30,51-63`。
- **触发/影响**：`collate()` 只有 `all("lit" in b for b in batch)` 才提供 `lit`；一个无亮图样本会使全 batch 亮图消失，CIC 不会应用于已有配对的样本。主消融“无 CIC vs 有 CIC”也因此可能比较不到预期的监督强度。
- **修复对齐**：batch 传递“是否配对”掩码并只提取对应实例，或使用单独的配对采样器；明确定义无配对样本的 CIC 贡献为零，不强制伪造亮图。
- **验收**：构造 [有配对, 无配对] 的 batch，有配对样本产生 CIC、无配对样本不参与；日志报告配对样本数、实例数及 CIC 有效 batch 比例。

### P0-10 识别训练使用 GT 中心线，推理使用预测中心线（确认：分布落差）
- **位置**：`seeread/models/seeread.py:42-50,67-83`；`seeread/models/tsr.py:27-66`。
- **触发/影响**：课程学习只替换高度；训练中心线永远来自标注，而推理由 text/center/geo 解码。识别器可能无法容忍错误中心线、漏字或相邻实例合并；这也是“端到端”主张需要如实界定之处：中心线/TSR 是不可微路径。
- **修复对齐**：在 val 上分别测 GT 框/GT 中心线/预测中心线的识别准确率，量化 gap；考虑匹配后的预测几何训练或扰动增强，且保留识别梯度仅能通过高度与光照上下文回传的准确表述。
- **验收**：同一模型报告 GT 几何与预测几何两套识别指标及误差来源；有训练/测试中心线来源记录。

### P0-11 合成集可能沿用源亮图的实例分档（确认：有前置条件）
- **位置**：`tools/make_synth_dark.py:11-20`；`tools/illum_stats.py:14-17`；`seeread/metrics/spotting.py:64,76`。
- **触发/影响**：如源 JSONL 已含实例 `bin`，合成脚本只改 `meta`、原样复制 `instances`；评测优先取实例 `bin`，导致暗图用亮图的档位。若源实例从未写 `bin`，则退化为图像级分档，不会发生“旧实例档位”问题。
- **修复对齐**：生成合成图后按合成像素重算实例级 `bin`，保留源档位时使用独立字段；同时记录仿真等级与实际亮度档，二者不要混为一谈。
- **验收**：输入已有 `bin=lit` 的源样本生成 extreme 暗图后，输出实例分档依据新图重新计算；分档直方图与抽样像素复核一致。

### P0-12 亮图“不退化”评测会被 `lit` 标记自动暗化（确认：条件问题）
- **位置**：`seeread/data/datasets.py:58-69`；`tools/eval.py:23`；`docs/01_research_design.md:110-115`。
- **触发/影响**：`illum_kind == "lit"` 的暗化没有 `self.train` 条件；即使 `train=False`，亮图仍被在线变暗。只有把亮图按该类型交给评测时触发，不能假定所有现有测试都会触发。
- **修复对齐**：明确“亮图原样评测”和“亮源图用于在线暗化训练”两种加载模式；离线合成测试集仍保持固定图像不重复暗化。
- **验收**：亮图在 val/test 加载时与原图像素一致；训练同一 `lit` 来源可在线合成；离线 `synth` 加载不再二次暗化。

## 2. P1：有条件触发的代码缺陷与重要实验缺口

### P1-01 识别阶段零有效文本 batch 会导致非 Tensor 反传（确认：条件问题）
- **位置**：`seeread/data/datasets.py:76-91`；`seeread/models/seeread.py:35-39,54-55`；`tools/train.py:49-51`。
- **触发/影响**：`stage=rec` 且所有实例均被忽略、裁掉或过小，返回 `{}`；`sum([])` 得整数 0，`scaler.scale(loss).backward()` 无法正常反传。
- **修复对齐**：采样前过滤无有效转写图，或在空损失 batch 显式跳过优化器/调度器步骤，并记录跳过数量；测试 `det/joint/rec` 三阶段行为。
- **验收**：空有效文本 batch 不崩溃，步数与 LR 调度只按真实更新计；日志有 skip 统计。

### P1-02 识别实例固定截断为前 16 个（确认）
- **位置**：`seeread/data/datasets.py:25-26,83-93`。
- **触发/影响**：`inst_rec[:self.max_inst]`，但检测目标已使用全部实例。文本密集图片超出 16 个时，后面的实例永远没有识别监督；是否影响大量图片需靠真实分布统计。
- **修复对齐**：先统计超过上限的占比；采用可配置上限、每轮随机/均衡抽样或分块识别，避免标注顺序永久决定监督机会。
- **验收**：每个有效实例长期有非零抽样机会；报告截断率和有效识别实例数。

### P1-03 CRNN 的 CTC 时间步限制可能吞掉长文本梯度（确认：条件风险）
- **位置**：`seeread/models/recognizer.py:39,44,48-60`。
- **触发/影响**：宽 128 经前两次宽度 2 倍池化，时间步约 32；目标过长或重复字符需要插入 blank 时可能无法 CTC 对齐，`zero_infinity=True` 会将无穷损失归零。真实触发率未知。
- **修复对齐**：统计编码后长度、连续重复数、CTC 所需最少步数；对超限实例调整输入宽度/序列模型或显式过滤与计数，而不是静默归零。
- **验收**：报告 `required_steps > T` 的占比为零或可解释；人为构造 33 字目标可被显式检出。

### P1-04 `rec` 阶段冻结参数但 BN running stats 仍可能更新（确认：条件问题）
- **位置**：`tools/train.py:32-33,44-45`；`seeread/models/seeread.py:33-40`；检测器在 `seeread/models/detector.py` 包含 BatchNorm。
- **触发/影响**：`requires_grad=False` 与 `no_grad` 不会自动让 BatchNorm 进入 eval；`model.train()` 后冻结检测器的 running stats 仍可改变。使用 `rec` 阶段且执行前向时触发。
- **修复对齐**：明确是否允许 BN 自适应；如需真正冻结，每 epoch 设置检测器 eval 并验证状态保持不变；如允许自适应，在论文中明确并控制公平性。
- **验收**：`rec` 前后对比检测器参数与 BN 缓冲区；变化与事先设定一致。

### P1-05 Resume 配置是空实现（确认）
- **位置**：`configs/base.yaml:39`；`tools/train.py:23-57`。
- **触发/影响**：`train.resume` 存在却未读取；checkpoint 只保存 det/enh/rec/配置，缺少 epoch、step、optimizer、scheduler、AMP scaler、最优验证指标与随机状态。长训练中断不能等价恢复。
- **修复对齐**：区分“初始化某阶段模型”与“完整断点续训”；后者保存/恢复模型、优化器、调度器、scaler、epoch/step、最佳指标、随机数及采样状态，并兼容旧权重文件仅做初始化。
- **验收**：同一环境在固定步骤中断后恢复，与不停机训练的权重/指标对齐到预设容差；旧 checkpoint 不能误称完整续训。

### P1-06 随机性管理不足以支撑跨环境严格复现（条件风险；此前“必然不可复现”不成立）
- **位置**：`tools/train.py:25-26,37-38,44-47`；`seeread/data/datasets.py:59`；`seeread/models/seeread.py:45`。
- **现状/影响**：worker 的 `torch.initial_seed()` 受 DataLoader 种子控制，**同环境同种子并非必然不可复现**；但样本增强依赖 worker 分配，改变 worker 数、批次或恢复位置可能改变同一图的暗化；CUDA 非确定性和恢复 RNG 状态也未管理。
- **修复对齐**：明确复现边界（同环境/跨 worker/断点）；如要求样本级一致，用 `(seed, epoch, sample_id)` 决定增强并为 shuffle 指定 generator；保存 Python/NumPy/Torch/CUDA 随机状态，对不确定性算子记录设置。
- **验收**：重复三次固定 seed 的样本 hash、日志和指标比较；跨 worker 数量测试与约定目标一致。不要仅凭 `torch.initial_seed()` 判为 bug。

### P1-07 忽略区匹配不是“所有命中均被吸收”（确认）
- **位置**：`seeread/metrics/spotting.py:44-72`。
- **触发/影响**：首个预测匹配 ignore GT 后仍把 GT 加入 `used`；同一区域后续预测无法再被该 ignore GT 吸收，可能计入 `n_pred` 使 precision 降低。是否符合某具体 benchmark 的官方实现，需要逐条核对协议。
- **修复对齐**：先定义与所选官方协议一致的 ignore-overlap 规则、阈值及是否可一对多吸收；单独处理 ignore 区，避免与有效 GT 一对一匹配混用。
- **验收**：一个 ignore GT 与多个完全落在其中的预测、与有效 GT 重叠等边界样例的预期指标明确且有单测。

### P1-08 小语种/转写规范与评测归一化需一致（条件风险）
- **位置**：`docs/02_dataset_protocol.md:27-30`；`seeread/models/recognizer.py:20-21`；`seeread/metrics/spotting.py:10-11,65-69`。
- **触发/影响**：评测去标点、大小写不敏感；训练编码却直接舍弃 OOV，训练目标与评测容忍度不自动等价。日/韩/阿等语言在默认字符集中完全不受监督。不能因为英文大写被转小写就声称它本身是严重 bug——须以目标任务的大小写定义判断。
- **修复对齐**：冻结原文转写、训练标签规范化、指标规范化三者的版本；按语种报告有效样本与 OOV，英文仅报英文子集时明确口径。
- **验收**：跨语种样本的训练编码与评测 normalization 一致；不存在文本被空编码却仍作为有效监督的情况。

### P1-09 光照阈值与物理合成参数尚未校准（确认：研究设计未完成）
- **位置**：`seeread/data/lowlight_synth.py:14-22,72-94`；`tools/illum_stats.py:13-18`；`docs/02_dataset_protocol.md:17-18`。
- **触发/影响**：`BIN_EDGES=(0,.04,.08,.15,1.01)` 与 `PHYS_LEVELS` 明写占位。若未经真实图分布校准，极暗/暗/弱光分组样本可能失衡，sim2real 解释不可靠。
- **修复对齐**：仅用训练集+验证集定义固定分档，公布阈值、每档实例数、曝光/设备分布与合成/真实直方图；最终测试集只应用冻结阈值，不依 test 分布反复重调。
- **验收**：分档的来源与版本可追溯；报告每档样本量及置信区间；合成不同等级确实覆盖目标真实分布。

### P1-10 实例亮度用外接框均值，不等于文字区域亮度（确认：度量选择）
- **位置**：`tools/illum_stats.py:14-16`；`docs/01_research_design.md:124-129`。
- **触发/影响**：实例级 `bin` 使用 polygon 外接矩形整个 patch，包含背景、霓虹或车灯，曲线文本尤甚；可能与“文字本身的曝光”不一致。该选择不是确定 bug，但会改变分档结论。
- **修复对齐**：预注册亮度定义（polygon mask 内均值、边界背景对照或外接框）；在 val 上做定义敏感性分析，阈值及计算方式固定。
- **验收**：至少在暗背景亮招牌、曲线文本、宽外接框样本上人工核验分档。

### P1-11 第三方 baseline 与 Oracle 仅是计划，不可生成有效对照（确认）
- **位置**：`seeread/baselines/llie_registry.py:14-20`；`scripts/run_baselines.sh:5-7`；`docs/01_research_design.md:133-145`。
- **现状/影响**：ZeroDCE/SCI/RUAS/SRDACE/GDP 适配器抛 `NotImplementedError`；B0（GT 框+识别）和 B1/B2（级联与通用 spotter）是注释，`tools/eval_oracle.py` 不存在。没有“最强级联/通用 spotter”结果，无法支持论文比较。
- **修复对齐**：优先实现 oracle、无增强级联与一到两个强公开 spotter；冻结数据划分、预训练来源、分辨率/训练预算、后处理与同一个评测器；之后再扩全量矩阵。注意官方权重许可证与可用性。
- **验收**：每个 baseline 有可重复运行命令、模型版本/权重、实际输出 JSON；同一测试样本可比对预测多边形与识别文本。

### P1-12 默认配置直接 joint；与研究结论的“提升来源”不易分离（确认：实验设计缺口）
- **位置**：`configs/base.yaml:29-41`；`configs/seeread_joint.yaml:1-2`；`configs/ablation_no_{ctx,cic,scm}.yaml`。
- **现状/影响**：现有消融只去掉 ctx/CIC/SCM；设计书还声称需证明 CSR、DSF、TSR、SnakeConvLite 等部件作用。若结果归因于仅三种开关，方法贡献不够可证伪。
- **修复对齐**：先定义严格可比的“相同训练/数据/预算 + 单项切换”实验，报告多种子均值方差，分离 detector backbone、几何矫正和亮图监督的效果。
- **验收**：论文每个主要模块至少有明确对照与相同评测口径；消融表不混入不同数据集或预训练流程。

### P1-13 测试仅有轻量 smoke，GPU/真实标注路径尚无验证证据（确认：覆盖缺口）
- **位置**：`tests/test_smoke.py:14-69`；`docs/01_research_design.md:169-174`；`results/`。
- **现状/影响**：小样本测试重点检查基本前向、CSR 梯度、单实例 TSR、简单评测。未覆盖混合配对 batch、无文本、长 CTC、非英文、训练/验证分离、断点/多 worker、真实 640×640/GPU/TrOCR。脚本存在不等于实际测试已通过。
- **修复对齐**：添加单元、数据契约、集成及 GPU 冒烟测试；先在小规模自造数据跑完整 train→val→eval，再跑真实数据。
- **验收**：保留测试命令、环境、版本、通过/失败日志；对每个 P0/P1 问题至少一个回归用例。

## 3. P2：工程稳健性与需消融的设计项

### P2-01 学习率无 warmup（确认：可选策略，并非必然 bug）
- **位置**：`tools/train.py:39-42`；`configs/base.yaml:31-35`。
- **现状/风险**：AdamW + cosine 从起始学习率 1e-4 开始，无 warmup；对预训练 ResNet/新头混合训练可能不稳，但无法无对照断言会失败。
- **修复对齐**：若观察到早期不稳定，再在 val 上比较线性 warmup 与无 warmup、backbone/head 分组 LR；记录总训练步数和重启调度状态。
- **验收**：固定种子下前期 loss、梯度范数与 val 指标支持选择，而非凭惯例加入。

### P2-02 `rec_k=7` 与检测 target `k=8` 不同（确认差异，**不是已证实的 bug**）
- **位置**：`seeread/data/datasets.py:25-26,84-88`；`seeread/data/geometry.py:30-36,48-51`。
- **现状/风险**：7 点用于识别矫正，8 点用于像素级检测监督；用途不同，未必要求一致。此前建议直接改成 7 缺少依据。
- **修复对齐**：可视化 GT map、中心线与识别 crop，测两种 k 的覆盖/识别结果；只有发现明显错位才统一或参数化。
- **验收**：曲线/斜文本可视化无明显偏移；选择由 val 指标支持。

### P2-03 配置 `_base_` 路径依赖斜杠计数（确认：特定调用方式下的稳健性问题）
- **位置**：`seeread/config.py:15-20`。
- **触发/风险**：当 config 路径无 `/`（尤其 Windows 反斜杠完整路径）时，相对基配置可能错误地按当前工作目录解析。现有 `configs/seeread_joint.yaml` 正斜杠调用通常不触发。
- **修复对齐**：统一以当前 config 文件所在目录解析相对 `_base_`，显式支持绝对基路径，并测试 cwd 改变和 Windows 路径。
- **验收**：同一 config 从项目根/其他工作目录、正反斜杠路径加载结果相同。

### P2-04 竖排/退化中心线的方向处理有限（确认：设计限制）
- **位置**：`docs/02_dataset_protocol.md:12`；`seeread/models/seeread.py:79-83`；`seeread/models/tsr.py:18-24`。
- **现状/风险**：极短中心线补点固定加减水平 `[2,0]`；默认阅读方向靠主轴判定，不适配所有竖排/双向文字。仅有该类样本时产生偏差。
- **修复对齐**：确定支持的语种和文字方向，不能支持的明确 ignore/分组报告；必要时用预测方向修补退化中心线、按标注阅读方向做排序。
- **验收**：水平/竖排/曲线和单点退化样例的裁剪可视化、阅读顺序与标注一致。

### P2-05 TSR 未实现实例间 NMS/分离，且与原论文实现有差异（确认：需验证影响）
- **位置**：`seeread/models/tsr.py:27-66`；`seeread/models/detector.py:1-7,17-43,46-61`；`docs/01_research_design.md:81-88`。
- **现状/风险**：基于连通域、FPS 和形态学处理，相邻文字可能粘连；SnakeConvLite 非官方 DSConv，通道注意力也与原文实现存在差异。不能将本实现数字直接等同官方 Seeing 复现。
- **修复对齐**：先复现论文官方基线/定位差异，再做原实现 vs Lite、TSR 后处理阈值/实例拆分消融；论文准确标注“重实现”。
- **验收**：近邻文本、弯曲文本和极暗样例的漏/并/碎检测计数与定性案例；明确版本来源。

### P2-06 SCM 损失权重与总损失的书面公式不完全一致（确认）
- **位置**：`seeread/models/seeread.py:35-37`；`seeread/losses.py:10-25`；`docs/01_research_design.md:91`。
- **现状/影响**：代码中的 `sr/ss` 不乘 `w.det`，而文档把它们写在 `λ_det` 的括号内；当前默认 `w.det=1` 时数值等价，改权重时才产生不一致。另外 `L_sr` 对 `gt["text"]` 做全图 L1，未使用 ignore 权重掩码（检测主损失用了 `weight`）。
- **修复对齐**：明确 SCM 独立权重还是统一归入检测权重；对 don't-care 区评估是否应屏蔽辅助损失；实验设置与公式一致。
- **验收**：非 1 的 `w.det` 和 ignore GT 的人工用例对得上书面定义。

### P2-07 `resume` 之外缺少模型来源及阈值元数据（确认：可追溯性不足）
- **位置**：`tools/train.py:56-57`；`tools/eval.py:18-34`；`seeread/models/seeread.py:68,77`。
- **现状/风险**：训练保存 `cfg=vars(cfg.train)`，不包含完整数据、模型、字符表和后处理阈值；评测依赖重新提供 config，若配置变化会产生“相同权重不同模型/口径”的风险。`max_det` 与阈值是固定参数，未展示 val 选择过程。
- **修复对齐**：checkpoint/实验清单写全配置快照、字符表、数据清单 hash、阈值、依赖版本；阈值只能 val 选择，eval 用锁定值。
- **验收**：只凭 checkpoint+清单能复现配置与预测，不依赖事后猜测。

### P2-08 配对图对齐工具只做 QC，不负责真正对齐标注坐标（确认：条件风险）
- **位置**：`tools/align_pairs.py:7-11`；`seeread/data/datasets.py:68-74`；`docs/02_dataset_protocol.md:20-24`。
- **触发/风险**：ECC 工具输出 shift 与 FLAG，但没有将 warp 应用于亮/暗帧或多边形；dataset 用 `cv2.resize` 尺寸对齐，不等于几何配准。若配对帧存在非平移错位，CIC 的暗/亮 crop 会对应不同笔画。
- **修复对齐**：记录 ECC 变换、相关性与残差；超阈值拒绝配对或真实施几何配准并更新标注坐标；用可视化复核。
- **验收**：亮暗文本边缘叠加残差在预定阈值内；bad pairs 不参与 CIC。

### P2-09 缺少多尺度/显存速度报告（研究完整性缺口，不要求直接改代码）
- **位置**：`seeread/models/seeread.py:68-90`；`tools/eval.py:23-34`；`docs/01_research_design.md:124-131`。
- **现状/风险**：默认单分辨率 `size=640` 与 stride 4，未见多尺度、推理耗时、显存统计的成品；对小文本/极暗文本性能和效率尚无证据。单尺度不是“代码 bug”。
- **修复对齐**：固定单尺度作为主指标；若做多尺度必须所有强基线公平对齐；报告 batch=1 含预/后处理的端到端 FPS、显存和参数量。
- **验收**：指标口径、设备、分辨率与阈值一致，可重复得到速度和准确率。

### P2-10 TrOCR 与其他分支尚未验证（确认：覆盖缺口）
- **位置**：`seeread/models/recognizer.py:68-102`；`tests/test_smoke.py:49-57`；`docs/01_research_design.md:169-174`。
- **现状/风险**：TrOCR+LoRA 需要外部模型/依赖；当前 smoke 只测试 CRNN 路径。中英文混合不能以英文 TrOCR 在全量集直接横比。
- **修复对齐**：用匹配的权重与依赖版本单独做前向、梯度和 checkpoint 测试；英文子集与全量多语种结果分开统计。
- **验收**：TrOCR 路径可独立运行且语种口径明确；未验证前不声称已经可复现。

## 4. 报告口径：之前说法的纠偏与未证实判断

1. **“项目完成度 40%、还需 6 个月”**：是粗略印象/设计书时间表，不是经过功能点或人力测量的事实；本清单以具体交付缺口代替百分比。
2. **“`torch.initial_seed()` 必然破坏重现”**：表述过重。PyTorch 多 worker 初始化通常可由同一主种子控制；真正需验证的是跨 worker 分配、重启、CUDA 与中断续训目标。
3. **“`rec_k` 不一致必然错位”**：不能直接推导；检测 mask 和识别 crop 用途不同，先做可视化/消融再决定修改。
4. **“大写、标点一律应保留”**：英文大小写折叠、去标点可能与当前评测协议一致。关键是多语种字符表、空编码回退和已冻结的规范化版本。
5. **“增加 warmup / 换回官方 DSConv 一定提高指标”**：未得到对照实验支持；只能作为验证方案。
6. **“该方向是首个/必可发表”**：目前缺系统近邻文献检索、基线复现和实测数字；不得使用已证实的 `first` 或既定发表前景措辞。
7. **“测试脚本多次运行就已经发生数据泄漏”**：不成立。风险来自**依据测试反馈作开发决策**；目前并无现成 test 数据或测试结果。
8. **“亮图 resize 的宽高参数写反”**：`cv2.resize(lit, (W,H))` 符合 OpenCV 的 `(width,height)` 约定；问题是尺寸缩放不代替几何配准，见 P2-08。
