# 审阅意见与任务重定（基于交接文档 + 20 例索引）

> 我只有文字，没有图片和代码。凡写"假设"的，都对应下面给出的无训练诊断。

## 1. 先确认哪些成立

- **评测器算术自洽**：det_P 0.4143 × rec_acc 0.0126 = e2e_P 0.0052；det_R 0.2149 × 0.0126 = e2e_R 0.0027；二者的 F = 0.0036，与报告值一致。e2e 这一步没有评测 bug。
- **亮光 e2e 的上界很低，与接口无关**：就算接口完美（GT 几何），e2e 召回 = 0.2149 × 0.128 ≈ **2.75%**（用 s3 rec 26.5% 也只有 5.7%）。**只修接口，e2e 最多从 0.3% 到 3–6%**。要两位数，检测召回和识别器必须一起上来。
- 暗光 e2e 贴着识别器的暗光上限，这一条成立。

## 2. 交接文档里推断过头或有混杂的地方

1. **"外延无效 → 推理端外延假设被否"，只否了外延。** 我给的三个修复里，路径排序和按预测方向定向都没被测试。"84–91% 是漂移/高度错"也与你们自己的证据矛盾：
   - 索引里 LOUIE（IoU 0.848）读成 aot、LINES（0.822）读成 lan、ROW（0.78）读成 now、SAN（0.75）读成 ae。
   - **多边形就是由这些预测中心点和预测高度累加出来的**。IoU 到 0.85，说明中心点和高度大体是对的。同一组点切出来的条带却读不出来，漂移和高度错解释不了，更像是**顺序/方向（180° 翻转）**，或**识别器对 crop 的边距、对齐极度敏感**。
   - 你们描述里的"翻转"二字，正是这个线索。
2. **R1（分辨率）被你们的证据削弱了，我要更正我之前的说法。** 20 例匹配实例在 640 画布里高度 18–122 px，多数 20–60 px，对 64 px 高的 crop 足够。分辨率不是匹配实例上 crop 失败的主因。但匹配集偏向大字，79% 的 GT 没匹配上，**分辨率仍可能是检测召回低的原因**。所以 P1 应改成"检测召回实验"，不是"crop 上限实验"。
3. **A 路 12.8% 本身就是灾难**：GT 几何、字高 20–60 px，词准确率只有 12.8%。这不是接口问题，是**识别器弱**（小 CRNN、仅 SynthText 训练、真实域缺口）。你们的 P1–P3 里**没有一项处理识别器**，P4 只是"冻结 vs 微调"。冻结 TrOCR 在 ICDAR 上 60.0%，**还没在 TT 上跑过**。
4. **B 臂 rec_acc=0.0000 不能当作"接口坏的干净证据"。** B 里 enhancer 和检测器同时在训练，冻结的 rec 面对的是漂移后的增强输出。恰好为 0 也值得查（是否 enh 学出了对冻结 CRNN 的退化输出）。
5. **增强器对照的预算太小，FAIL 只能在该预算下成立。** 每个变体从零训 2000 步，所有变体都贴近地板，差异必然小于 2pp。判据按预注册是 FAIL，没问题；但结论只能写"该协议下无可靠增益"，**不能延伸成增强器无用**。
6. **"S1 只训 1 epoch → det_F 0.28"证据偏弱。** 26,835 iter × bs32 并不算少；"loss 0.654→0.886 未到平台"是单批 loss，噪声大，不能当趋势。更可能的原因：TT 域检测适配薄（老师流程是 SynthText 2 ep → MLT 100 ep → 目标集微调）、自己重实现的 DSF/SCM/TSR 与官方有差异、后处理阈值。
7. **检测 P 与 R 都低**（P 0.41, R 0.21）：不只是漏检，还有大量错误预测（碎片/合并）。这和"多边形几何不准导致 IoU<0.5"同源，需要用 IoU 阈值扫描区分。
8. 小一致性：§3.1 把召回上界（5.7%）和 e2e_F（0.36%）比；ceiling 同时混用了 s2 和 s3 两个 rec。写论文前统一口径。

## 4. 要不要删减架构：我的意见

**证据不支持保留的部分**
| 模块 | 证据 | 建议 |
|---|---|---|
| 光照感知增强器 IAE（FiLM 上下文） | 预注册对照 FAIL（受预算限制）；e2e 路径里无增益 | 移出主方法，降为"负结果/消融"；主方法里用恒等映射 |
| 端到端联合微调（S3）及可微几何 CSR | 联合训练把 rec 练坏；A/B 都没有收益；没有做过 CSR 消融 | 不再宣称"端到端耦合"；改为模块化：检测冻结，识别器单独训 |
| 自己重实现的 DSF/SnakeConvLite/SCM/TSR | det_F 0.28，与已发表的 88.5 差 3 倍；没有任何一项被验证 | **向老师要官方检测器代码和权重**（他是作者）。拿不到就用现成强检测器（如 DBNet++ 一类）微调，别再投入重实现 |
| 自训小 CRNN | GT 几何下 12.8–26.5% | 换预训练识别器（TrOCR+LoRA 或 PARSeq），英文 TT 评测先用它 |

**应该保留、已被验证的资产**
- 逐瓶颈归因方法（检测 × 几何 × 识别），以及按光照分档的评测协议。
- 合成 vs 真实的跨分布勘误（oracle 在 SynthText 上 68%，TT 上 14.6%，差 4–40 倍）。
- 混合检测数据的收益：CTW、dark CTW、LATeD 的 det_F 有实质提升（LATeD +7.7pp）。
- LATeD 真实暗光检测基准，以及（待做的）转写子集。

## 5. 任务如何更改

**从"提出新方法"改为"真实暗光 spotting 基准 + 诊断研究 + 一个朴素但强的基线"。** 原因：方法侧的每个创新点目前都没有正收益证据，而归因、勘误和真实暗光检测数据是真正站得住的。

建议的论文主张（每条都要有实验支撑，没有就删）：
1. 一个带光照分档协议的真实暗光检测/spotting 基准（LATeD 检测，加上标注 ≥2000 实例的转写子集）。
2. **诊断研究**：e2e = 检测 × 几何 × 识别，各因子在不同光照档位的损耗；合成暗化 oracle 与真实分布的数量级差距；曲线增强器在预算充足时是否真的无益（需要重做对照，见下）。
3. **基线配方**：强预训练检测器 + 强预训练识别器 + 暗光微调 + 用检测器自己输出的 crop 训练识别器（detector-in-the-loop crops，覆盖真实的翻转、边距、漂移误差分布）。这比我之前提的合成扰动更贴近真实误差。
4. 若时间允许：配对的真实暗光/手电采集（约 200 场景），给识别和暗光合成校准提供真实监督。

## 6. 新的实验顺序

1. **D1–D7（半天，无训练）**，其中 D5、D4、D1 优先。
2. 联系老师要官方检测器；同时确认他们的 TT 评测设置。
3. 识别器：换 TrOCR/PARSeq，GT 几何先看亮、暗各多少；再加真实词图（IC15 train、TT train、LSTR 亮图原图）与 detector-in-the-loop crops、rot180 增强/方向分类。
4. 用 crop 级词准确率（GT 几何与预测几何各一套，≥几百词）选模型，别用 val e2e。
5. 增强器对照重做：预训练识别器 + 足够步数 + 多种子，再判断去留。
6. LATeD 转写子集（≥2000 实例）；叙事在步骤 3–5 之后定。

## 7. 暗光侧在没有真实暗训练数据时的杠杆（回答 §8-Q4）
- 预训练强识别器 + 暗光噪声感知微调（Poisson–Gaussian、真实亮度分布校准），比从零训强得多，也是对增强器最公平的对照。
- 外挂成熟的去噪/低光增强做冻结预处理，测它对词准确率的影响（避免自己的曲线增强器不能去噪的问题）。
- 自采配对的真实暗/亮数据（小量也有价值）。
- 对 LATeD 的 4808 个无转写实例，用强识别器做伪标签只能做一致性/自训练，不能当评测依据。
